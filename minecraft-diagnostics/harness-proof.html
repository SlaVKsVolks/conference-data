What The Harness Does

Phase markers Records boot, resource reload, model bake, shader initialization, menu visibility, world readiness, route completion, and cleanup phases.
Route-aware attribution Separates first-load and route-critical windows from later background work, which helps identify whether a mod is blocking launch, world entry, or gameplay.
Runtime evidence Captures heap, non-heap, cleanup, scheduler, and mod-specific event signals that can be condensed into buyer-readable findings.

Signals Already Covered

  • NeoForge 1.21.1 client/server lifecycle hooks.
  • Xaero world-map route work execution and deferral counters.
  • Voxy direct-entry renderer lifecycle compatibility signals.
  • Sodium chunk upload backlog and frame-budget pressure.
  • EMI, JEI, ClientSort, YACL, and Advanced Loot Info startup deferrals.
  • ResourcefulLib, Connector Extras, Inventory Particles, and shader/model cleanup events.
  • Network/config payload diagnostics for startup handshake failures.

Buyer-Facing Output

A harness-backed mini-audit is still delivered as a plain written report. The buyer does not need remote access, credentials, or private server control.

You send

  • Crash report or latest.log
  • Minecraft version and loader
  • Modlist if available
  • What changed before the issue started

I return

  • Likely cause category
  • Suspicious line, mod, class, or phase
  • First safe fix steps
  • When useful, what deeper harness run would test next
